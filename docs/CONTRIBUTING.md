# Contributing to Programming in NeoAda

## Style

- Prefer short sentences and concrete examples.
- Introduce one new concept at a time in beginner chapters.
- Use NeoAda type names consistently.
- Distinguish mutating from copy-returning operations.
- Do not claim behavior that has not been verified.
- Do not describe NeoAda as safety-certified unless a specific certification scope exists.

## Code examples

Runnable examples use fenced blocks tagged `neoada`. Conceptual examples must say they are conceptual. Where possible, execute examples in CI with the current interpreter.

## Chapter pattern

Idea → minimal example → explanation → larger example → common mistakes/design guidance → exercises.
